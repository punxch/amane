# 图片与按站字段列表化

---
Status: accepted
---

条目的图片与预告按列表存放（`poster_urls` / `thumb_urls` / `trailer_urls`），剧照、评分、外部标识、原站地址按站点分组（`extrafanart_urls` / `scores` / `external_ids` / `source_urls`）。单值不再落库，读取时从列表首项派生。剧照只存地址，不下载。

## 考虑过的方案

- **保持单值 + 依赖来源快照**：详情页只能显示一张图；评分按站存的语义无处安放，而 dmm 与 javdb 的评分本来就不可比。
- **列表与单值列并存**：两份真值迟早分叉 —— 列表更新而单值列还是旧值时，界面与资源任务会读到两个答案。迁移是一次性的，重建表的代价只在一次升级里付。
- **物化全部剧照**：一次刮削可能拉回几十张图，资源任务与磁盘都会被单条条目撑爆。剧照地址随条目存，需要时再取。

## 后果

- 迁移要重建 `metadata` 表（SQLite 删列只能重建），旧单值塞进列表首项，`cover_url` 归入 `thumb_urls`。
- 对外契约形状不变：DTO 的 `poster_url`、`cover_local_url` 等仍是单值，由首项投影得出。
- 资源任务仍只处理两张图；想显示剧照得走远端地址，离线时不可用。
