# 来源自声明速率

---
Status: accepted
---

来源在编译期声明自己请求的主机名与每秒请求数，装配层遍历登记表建出按 host 分桶的限速表；同一 host 上有多个来源时取更保守的一份，热配置的 `host_rates` 可按 host 覆盖。

## 考虑过的方案

- **速率写在装配代码里**：现状如此，两个来源时够用。二十多个来源之后那里会变成一张与站点实现分开维护的表，新增来源必须记得去改两处，漏改的后果是被站点封。
- **每个来源一个限速器**：站点看到的是同一台主机上的总频率，来源各算各的等于没限速。分桶必须按 host。
- **同一 host 取更快的值**：站点只认总频率，快的那份会让它收到没答应的请求。取保守值是唯一不会因此被封的选择。
- **配置替换来源声明**：用户不知道站点能承受多少，只能表达「比现在慢」。声明是默认值，覆盖是临时放慢，两者叠加而不是互斥。
- **换速率时重建客户端**：`WebClient` 持有连接池与指纹状态，重建会丢掉它们。限速表改成运行期可整体替换，已建立的桶保留令牌数，下一次取令牌即按新速率补充。

## 后果

- `SourceDescriptor` 多两个字段（`host`、`rate`），新增来源必须给出；漏给编译不过。
- 未声明速率的 host（图片 CDN 一类）落到兜底速率，仍是同一条限速通道。
- `host_rates` 的覆盖只给每秒次数，突发上限按 1 处理：用户要的是「放慢」，不是「还能瞬间打一串」。
- 覆盖后不重启即生效；速率表的键是主机名，站点换域名要连 `host` 一起改。
