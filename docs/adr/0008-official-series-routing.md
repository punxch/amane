# 片商官网只按系列前缀路由

---
Status: accepted
---

片商官网是一个来源、29 个域名。路由只做一级：番号的系列前缀查表得到制作商，拼出 `https://{域名}/works/detail/{番号去分隔符}`。不做「按前序来源的片商名反查」这一级。

## 考虑过的方案

- **照 Python 的三级回退**（配置前缀 → 系列表 → 前序片商名别名）：第三级要读聚合结果，而 `Source::fetch` 只拿得到番号。给来源加一个「读前序结果」的入参，等于让每个来源都能依赖链上位置，代价远大于它救回来的那几种情况。
- **每家厂牌一个来源**：29 个来源挤在链尾，链的语义会被这一家撑坏，且它们的解析器是同一份。
- **只接一家厂牌**：覆盖太少，official 在链尾的意义（补 dmm 与索引站都没有的字段）就没了。

## 后果

- 前缀表覆盖不到的系列，official 报未收录，不会退到「猜一个域名」。
- 新系列要补 `SERIES` 表；表与 `MANUFACTURERS` 之间有一致性用例兜底。
- 29 个域名各占限速表的一个桶，速率都是 1/s；来源声明因此从单个 `host` 改成 `hosts`。
- 图片落在各家自己的 CDN 上，未声明速率，走兜底速率。
