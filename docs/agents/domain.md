# 领域文档

工程技能探索代码库时按下述规则读取领域文档.

## 探索前先读

- **术语表**: `docs/dev/terms.md`. 本仓库不设根 `GLOSSARY.md`, 术语只有这一处来源.
- **架构决策**: `docs/adr/`, 读取涉及当前工作的条目.
- **表达规范**: `docs/dev/writing.md`, 输出 issue 标题、重构提案、测试名称时遵守.

文件不存在时静默跳过, 不提示缺失, 也不提议预先创建. ADR 由 `domain-modeling` 在实际确定决策时按需生成.

## 目录

    /
    ├── docs/dev/terms.md     术语表
    ├── docs/adr/             架构决策
    └── src/

## 使用术语表的用词

输出中出现领域概念时 (issue 标题、重构提案、假设、测试名称), 使用 `docs/dev/terms.md` 的定义, 不漂移到该文件排除的说法.

概念不在术语表中时视为信号: 要么正在发明项目不使用的语言 (重新考虑), 要么确实存在空缺 (交由 `domain-modeling` 处理).

## 标记 ADR 冲突

输出与既有 ADR 冲突时明确标记, 不静默覆盖:

> _与 ADR-0007 冲突 (……), 但值得重新讨论, 理由是……_
