# 架构

> 只记录**为什么**这样划分以及**什么时候会失效**. 签名与字段去源码。

## crate 边界

| 路径 | 边界 | 不变量 |
|------|------|--------|
| `crates/core/` | 番号、条目、媒体库扫描、配置、持久化 | 不依赖传输层; 不引入 `utoipa`; 无全局可变状态 |
| `crates/crawlers/` | 来源契约 `Source`、能力声明、登记表 `Registry` | 无状态; HTTP 客户端与配置在构造期注入; 站点实现编译进二进制 |
| `crates/net/` | 出站 HTTP: 浏览器指纹、按 host 限速、被拒后轮换 | 不感知站点语义; 限速器先于客户端构造, 由类型签名保证 |
| `crates/runtime/` | 任务处理函数 (刮削、扫描、资源物化) | 依赖 core、crawlers 与 net; 只做编排与写库, 不实现解析与抓取 |
| `crates/server/` | axum 路由、DTO、错误映射、OpenAPI | 不持有业务规则; 领域类型到 DTO 的转换只在此层 |
| `crates/desktop/` | Tauri 外壳 | 只做装配: 生成令牌、绑定端口 0、打开窗口指向内嵌服务 |
| `ui/` | Vue 3 前端 | 只经 HTTP 契约访问后端, 不读取本机文件或数据库 |

领域类型与传输 DTO 分开 (`amane_core::Metadata` 与 `server::dto::MetadataDto`): 新增接口字段不会波及内核, 内核对宿主形态无感知。

## 启动顺序

`Runtime::boot` 的顺序不可颠倒:

```
冷配置 → 创建数据目录 → 打开数据库 (含迁移) → 仓储 → 恢复遗留任务
       → 来源登记表 → 处理函数表 → 任务运行时 → 路由装配
```

- **迁移在仓储之前**: 仓储的第一条查询假设表已存在。
- **恢复遗留任务在启动出队循环之前**: 顺序颠倒会让上次进程遗留的任务一直停在运行中。
- **来源登记表与处理函数表在任务运行时之前**: 运行时按类型查表, 缺表会把任务判成「没有注册处理函数」。
- **出队与调度循环由进程入口启动, 不在 `Runtime::boot` 内启动**: 测试装配路由时不希望后台线程自行领取或派生任务。

## 列表与筛选

- 筛选条件集中在 `MetadataFilter`, 组合时取交集; 字段的新增只改这一处。
- `list` 与 `count` 共用 `push_conditions`, 两处条件不会漂移; 命中总数与列表始终同源, 翻到末页不会出现「总数还有但列表为空」。
- 来源筛选走 `source_snapshot` 的 `EXISTS` 子查询, 因此「该来源贡献过内容」与「该来源曾命中」是同一件事。
- 关键字用 `LIKE`, `%` 与 `_` 在拼模式前转义; 不转义时搜 `100%` 会命中全部条目。
- 取值域有界的筛选值 (类型、来源) 由服务端拒绝未知取值并返回 400, 不静默返回空列表 —— 否则拼错一个字母看起来就像没有数据。可选项由 `GET /api/filters` 从枚举与来源登记表给出, 界面不自行维护枚举。

## 锁定与人工修订

- 锁定以「番号条目 + 字段」为单位记录, 字段取自 `LockableField`; 演员名单不在其中, 它是整体替换的列表, 没有逐项修订的语义.
- 刮削写入走 `apply_scraped`: 在同一事务里读取锁、剔除锁定字段、写行、按字段合并来源. 分成多次读会让「加锁」与「刮削」交错时丢掉刚写入的人工值.
- 被锁定的字段以 `None` 参与 `COALESCE` 写入, 因此保留原值; 解锁后下一次刮削即可覆盖, 无需额外确认.
- 手工修订 (`PATCH`) 会同时做两件事: 把字段来源记为 `manual`, 并给该字段加锁. 只记来源不加锁, 下一次刮削就会覆盖人工值, 与「手工值不被覆盖」的承诺矛盾.
- 海报字段锁定后跳过下载; 未锁定时下载所依据的是写入后的 `poster_url`, 而不是本次刮削返回的地址.
- 标签按名字去重 (`user_tag.name` 唯一), 移除关联时不留下无人引用的标签名.

## 持久化

- 写池固定单连接, 读池多连接, 两者指向同一库文件。SQLite 同一时刻只允许一个写者, 多写连接会退化为忙等。
- WAL 与 `synchronous = NORMAL`: 读不阻塞写, 进程崩溃可能丢最后若干事务, 但不损坏库。
- 迁移经 `sqlx::migrate!` 在启动期自动应用; `migrations/` 只新增文件, 已应用的迁移不修改。
- 时间列以 UTC 存储, 由 `chrono::DateTime<Utc>` 与 TEXT 互转。

## 资源

- `resource` 以远端地址为键去重; 文件名在取得标识后才确定, 因此先插入再回写。
- 写入磁盘失败时撤销登记, 避免库里留下没有文件的资源。
- 类型以文件头为准, 上游声明的 `content-type` 只作参考; 不一致时记录告警。
- 资源端点以标识取内容, 内容不可变, 因此返回长期缓存头。
- 海报下载失败不改变任务终态: 条目已写入, 缺图是允许的降级, 详情页据此提示。

## 运行时替换

热配置变更不重启进程: 整体重建 `Runtime` 并原子替换, 请求持有所在 `Runtime` 的 `Arc` 执行完毕。字段之间不存在半新半旧的组合。

顺序约束: 限速器必须先于 HTTP 客户端构造 (`WebClient::new` 接受 `RateLimiters`, 颠倒无法通过编译), 来源登记表必须先于爬虫工厂。客户端与限速器见 [network.md](network.md)。

## 传输契约

- 端点全部注册在 `/api` 下, 前端与 Docker 部署共用同一份契约。
- 访问令牌非空时校验 `Authorization: Bearer <token>`, 只作用于 `/api`; 静态文件不校验。
- 错误响应统一为 `{ "code": ..., "message": ... }`, 由 `ApiError` 映射到状态码; 仓储错误在映射时记录日志, 响应体不携带内部细节。查询参数解析失败也走这一形状 (`invalid_query`), 否则框架默认的纯文本 400 会让界面拿不到错误码。
- `AMANE_UI_DIR` (默认 `ui/dist`) 存在 `index.html` 时, 同端口提供前端产物: 命中文件按扩展名返回, 未命中回退到 `index.html` 并返回 200, 使单页应用的深链接可直接打开。越界路径不读库外文件, 一并回退到入口页。不使用 `ServeDir::not_found_service` — 它保留 404, 只适用于自定义错误页。
- OpenAPI 由 `utoipa` 编译期生成, `--print-openapi` 输出到标准输出; 版本号取自 `CARGO_PKG_VERSION`。

## 媒体库扫描

- 归类优先级固定: 系统产物 → 黑名单 → 大小阈值 → 扩展名。黑名单先于大小判定, 否则大于阈值却命中黑名单的文件会被当成正常媒体放行; 命中的规则原文写进 `detail`, 界面据此说明「为什么被挑出来」。
- 扩展名不匹配任何规则的文件归入「未识别」单列一档, 不静默消失; 子树里没有媒体文件的目录记为「残留目录」, 只报真正的空叶, 含媒体的祖先不算。
- `.amane_trash` 目录整个子树剪枝, 交给清理切片; `.strm` 是路径指针, 算媒体入口但大小过滤对它无意义。
- 扫描是任务 (`TaskKind::Scan`), 不在登记请求里同步执行: 大目录的遍历是纯阻塞 IO, 处理函数放进阻塞线程池, 不占异步工作线程。
- 索引按根目录整体替换并与增量比较放在同一事务里: 中途失败不会留下半个库的索引; 路径集合用 `BTreeSet`, 两次扫描的日志顺序稳定。
- 扫描规则 (扩展名、阈值、黑名单) 在每次扫描开始时从配置快照编译: 热配置改动不需要通知处理器, 下一次扫描自然生效; 非法正则在配置提交时就被拒绝, 不等扫描才炸。

## 配置

冷热两层分离: 冷配置 (数据目录、监听地址、令牌) 修改后需重启; 热配置 (并发、超时、启用来源) 由运行时重建生效。配置 schema 由 `schemars` 从同一份类型生成, `x-widget` 等表单提示写在字段属性上, 前端按 schema 渲染表单。
