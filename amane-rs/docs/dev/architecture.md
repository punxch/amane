# 架构

> 只记录**为什么**这样划分以及**什么时候会失效**. 签名与字段去源码。

## crate 边界

| 路径 | 边界 | 不变量 |
|------|------|--------|
| `crates/core/` | 番号、条目、配置、持久化 | 不依赖传输层; 不引入 `utoipa`; 无全局可变状态 |
| `crates/crawlers/` | 来源契约 `Source`、能力声明、登记表 `Registry` | 无状态; HTTP 客户端与配置在构造期注入; 站点实现编译进二进制 |
| `crates/server/` | axum 路由、DTO、错误映射、OpenAPI | 不持有业务规则; 领域类型到 DTO 的转换只在此层 |
| `ui/` | Vue 3 前端 | 只经 HTTP 契约访问后端, 不读取本机文件或数据库 |

领域类型与传输 DTO 分开 (`amane_core::Metadata` 与 `server::dto::MetadataDto`): 新增接口字段不会波及内核, 内核对宿主形态无感知。

## 启动顺序

`Runtime::boot` 的顺序不可颠倒:

```
冷配置 → 创建数据目录 → 打开数据库 (含迁移) → 仓储 → 来源登记表 → 路由装配
```

- **迁移在仓储之前**: 仓储的第一条查询假设表已存在。
- **来源登记表在装配前构造**: 路由不感知具体站点, 只持有 `Registry`。

## 持久化

- 写池固定单连接, 读池多连接, 两者指向同一库文件。SQLite 同一时刻只允许一个写者, 多写连接会退化为忙等。
- WAL 与 `synchronous = NORMAL`: 读不阻塞写, 进程崩溃可能丢最后若干事务, 但不损坏库。
- 迁移经 `sqlx::migrate!` 在启动期自动应用; `migrations/` 只新增文件, 已应用的迁移不修改。
- 时间列以 UTC 存储, 由 `chrono::DateTime<Utc>` 与 TEXT 互转。

## 运行时替换

热配置变更不重启进程: 整体重建 `Runtime` 并原子替换, 请求持有所在 `Runtime` 的 `Arc` 执行完毕。字段之间不存在半新半旧的组合。

顺序约束: 限速器必须先于 HTTP 客户端构造, 来源登记表必须先于爬虫工厂; 颠倒会得到旧客户端。首个切片尚未引入 HTTP 客户端与限速器, 引入时上述顺序同样成立。

## 传输契约

- 端点全部注册在 `/api` 下, 前端与 Docker 部署共用同一份契约。
- 访问令牌非空时校验 `Authorization: Bearer <token>`, 只作用于 `/api`; 静态文件不校验。
- 错误响应统一为 `{ "code": ..., "message": ... }`, 由 `ApiError` 映射到状态码; 仓储错误在映射时记录日志, 响应体不携带内部细节。
- `AMANE_UI_DIR` (默认 `ui/dist`) 存在 `index.html` 时, 同端口提供前端产物: 命中文件按扩展名返回, 未命中回退到 `index.html` 并返回 200, 使单页应用的深链接可直接打开。越界路径不读库外文件, 一并回退到入口页。不使用 `ServeDir::not_found_service` — 它保留 404, 只适用于自定义错误页。
- OpenAPI 由 `utoipa` 编译期生成, `--print-openapi` 输出到标准输出; 版本号取自 `CARGO_PKG_VERSION`。

## 配置

冷热两层分离: 冷配置 (数据目录、监听地址、令牌) 修改后需重启; 热配置 (并发、超时、启用来源) 由运行时重建生效。配置 schema 由 `schemars` 从同一份类型生成, `x-widget` 等表单提示写在字段属性上, 前端按 schema 渲染表单。
